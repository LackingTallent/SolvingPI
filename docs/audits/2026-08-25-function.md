# Solving PI v9 — Functional Audit (report only, nothing fixed)

Audited: `/home/claude/rebuild/solving-pi-v9` — `static/index.html`, `static/legacy/*.js`,
`src/ui/app.ts` + `src/ui/state.ts`, `tools/build.mjs`, `tools/smoke.mjs`, `netlify.toml`, `static/css/*`.

Verification method: full read of every file plus an empirical load of the built `dist/` in headless
Chromium with console capture. Two uncaught load-time errors were **observed live**, not just predicted:

```
Uncaught ReferenceError: p0PerDayForProgram is not defined   — legacy/01-data.js:963
Uncaught SyntaxError: Identifier 'IMPORTED_TEMPLATES' has already been declared — legacy/21-templates.js:1
```

In that same live run: `#tplTables` was empty, `#tplCount` was empty, while the module app booted
(`data-smoke="ok"`, `data-selftest="pass"`) and the market legend rendered 7 columns.

---

## Defect list

### BROKEN — will throw, or a control does nothing when used

**1. The entire PI Templates feature is dead: `21-templates.js` fails to parse (duplicate top-level `const` with `20b-imported-templates.js`).**
`static/legacy/21-templates.js:42` declares `const IMPORTED_TEMPLATES` (also `IT_GROUP…IT_TEXT` at :251,
`TEMPLATE_SOURCES` at :253) which `static/legacy/20b-imported-templates.js:37/:246/:248` already declared —
21 was built as "20b + 21 + panels concatenated" (its own header, `21-templates.js:1-5`, says block 1 is the
*entire* 20b file), yet `static/index.html:613-614` loads **both** scripts. Duplicate lexical declarations
across classic scripts are a `SyntaxError` at global-declaration-instantiation, so **nothing in 21 ever
executes**: no `buildMinerTemplate`/`buildP2FactoryTemplate`/`eveSerialize`/`templateForColony`, and
`initTemplateLibrary` (21:844-1032) never runs. Observed effect: `#tplTables` (index.html:412) stays empty,
`#tplFilter` (:409) and `#tplCount` (:410) are dead, every "Copy" template button never exists — the
"1-Click Import PI Templates" hero stat jumps to an empty section.
*Fix: remove the `20b-imported-templates.js` script tag from index.html (21 contains all of 20b), or strip block 1 out of 21.*

**2. `01-data.js` throws an uncaught `ReferenceError` on every page load: `p0PerDayForProgram` was never carried over.**
`static/legacy/01-data.js:963` — `const P0_PER_DAY_BASELINE = p0PerDayForProgram(6);` runs at script-execute
time; the function lived in a v8 engine module (13-engine/15-allocator family) that v9 did not carry, and no
shim defines it (grep: zero definitions anywhere under `static/`). Execution of 01-data stops at line 963,
so every `const` after it stays in its temporal dead zone forever: `MAX_RESOURCES_PER_COLONY` (:964),
`P1_TO_P0` (:965), `MAX_CHARACTERS`/`MAX_PLANETS`/`MAX_PLANETS_PER_CHARACTER` (:985-987),
`TIER_BASE_COSTS` (:1010), `CUSTOMS_IMPORT_MULTIPLIER` (:1013), `CUSTOMS_COMMAND_CENTER_MULTIPLIER` (:1018) —
any future access throws. Today no carried file reads them (grep confirmed), and hoisted functions
(`baseCostOf`, `iconImg`, `esiFetch`…) survive, so the blast radius is "console error + landmines", but it is
a guaranteed uncaught exception on every single load.
*Fix: carry the v8 `p0PerDayForProgram` into 00-shims, or delete the `P0_PER_DAY_BASELINE` line (nothing uses it).*

**3. The Zelle donate button does nothing and the Zelle modal can never open or close — v8's 22-panels open/close block was never extracted.**
`static/index.html:586-593` (`#zelleBtn`), `:535-547` (`#zelleModal`, `#zelleClose`). Grep across
`static/legacy/` and `src/`: **zero** references to any of the three ids (10-shell carried the help modal
block, 22-panels.js:620-665, but not the Zelle block). The modal ships `hidden` with working CSS
(`.zelle-modal[hidden]{display:none}`, 02-app.css:633) and no JS ever unhides it: a visible footer button
that silently does nothing when clicked.
*Fix: port the ~15-line v8 zelleBtn/zelleClose/backdrop-click open-close block into 10-shell.js.*

### DEGRADED — runs, but wrong or partial

**4. Market Reference hover popup prints `undefined` as the system name: `readPlanets` bridge omits the `system` field the popup reads.**
`static/legacy/19-market-grid.js:212-215` builds rows as `{planet: pl.name, system: pl.system, …}` and
renders `${r.system}` (:238); `src/ui/app.ts:653-659` (`readPlanetsForLegacy`) returns only
`{name, type, densities}` — no `system`. Every populated popup row shows the literal string "undefined"
in the amber system slot. (`densities` as `{p0: pct}` and `name` do match; nothing else is read — no sec2 DOM.)
*Fix: add a `system` field to the bridge shape (store it on UiPlanet or split it out of `name`).*

**5. Batch-imported planets get double-prefixed names ("T-Q2DD T-Q2DD XI").**
`static/legacy/23-screenshot.js:645-646` sends `name = r.planet.value`, which is already
`"<SYSTEM> <ROMAN>"` (`extractPlanetName`, 23:204-208 returns `h.system + ' ' + h.numeral`), plus
`system: sysName`. `src/ui/app.ts:635` then builds `` `${bp.system} ${bp.name}` `` — duplicating the system
prefix on every successfully OCR'd planet (and prefixing "Unknown system" onto filename fallbacks).
Also breaks the dedup-by-name match (:636) against any hand-entered planet.
*Fix: in deliverBatch, use `bp.name` as-is when it already starts with `bp.system`.*

**6. Hero jump fires `section:expanded` twice → System Status double-loads (two ESI `/status` calls, racing renders).**
`static/legacy/00-shims.js:56-60` — `setCollapsed(sec,false)` dispatches `section:expanded`;
`static/legacy/10-shell.js:128` calls it and then :135 dispatches the same event again unconditionally.
19 and 22 survive via `loaded` guards (19:186-193, 22:20-21), but 24-status's `load()`
(`static/legacy/24-status.js:18-80`, listener :82) has **no** guard (its `loaded` flag is set but never
checked), so one click on the "Works / Most Of The Time" hero stat issues two concurrent ESI status fetches
and renders `#statusGrid` twice.
*Fix: delete the second dispatch at 10-shell.js:135 (setCollapsed already announces), or guard `load()`.*

**7. Clicking to COLLAPSE the Status section fires a fresh ESI status load.**
`static/legacy/24-status.js:83-85` attaches a direct listener to the section's `.collapse-btn` that loads
when the section is "not collapsed" — but a target's own listener runs **before** the document-level
delegated toggle in 00-shims.js:61-66, so on a collapse click the class check still reads "expanded" and
`load()` fires while the panel closes. (22-price-history.js:159-161 has the identical pattern but is saved
by its `loaded/loading` guards.) The expand path is not double-fired only because the same ordering makes
the button-listener check fail before the toggle.
*Fix: drop both direct collapse-btn listeners — the `section:expanded` event already covers expansion.*

**8. ~10 ESI requests are burned on every page load for data nothing consumes.**
`static/legacy/01-data.js:862` — `loadAllSystems()` runs at load, fetching `universe/systems` plus ~9
chunked `universe/names` POSTs into `ALL_SYSTEMS`. The v8 system-autocomplete that consumed it was not
carried; grep shows zero consumers of `ALL_SYSTEMS`/`systemsLoadFailedChunks` outside 01-data itself.
Pure ESI-budget waste (the same budget 24-status reports on).
*Fix: remove the eager call (keep the function if a future system field wants it).*

**9. The smoke test cannot catch defect #1 — its "templates library rendered" check passes on the empty mount.**
`tools/smoke.mjs:58` — the third alternative `dom.includes('tplTables')` matches the bare
`<div id="tplTables">` in the static HTML, so the check reads green while 21-templates.js is a parse-time
corpse (observed in the live run: check-string present, zero rendered rows). :57's market-grid check has the
same weakness (`dom.includes('legendGrid')`). The suite also ignores console errors, so defect #2 sails
through as well.
*Fix: assert on rendered output (`tpl-row`, a non-empty `#tplCount`) and fail the run on any uncaught console error.*

**10. Batch UI shows bridge-rejected planets as successes.**
`static/legacy/23-screenshot.js:663-668` marks a result row `bad` only from OCR state
(`!r.ok || !r.readings.length`); planets the bridge rejects — `src/ui/app.ts:628-629` (unmatched planet
type, which `matchPlanetType` (23:73-81) returns for any screenshot with <3 recognized resources) or :634
(no legal resources) — are added to the "failed" count (23:652-654) but their list rows still render with
success styling and full density text. The user is told "N failed" with no way to see which or why.
*Fix: have deliverBatch return per-planet verdicts and mark those rows bad.*

**11. Results (section 5) are never invalidated: edit anything, the stale solve stays up.**
`src/ui/app.ts:674-679` — `rerender()` repaints sections 1-4 only; `#resultsPanel` and `#sec4Summary`
persist a previous solve (against old planets/prices/goal) with no staleness marker after any state
mutation. Requiring an explicit re-Solve is fine; showing an unmarked stale answer next to changed inputs
is not.
*Fix: on state mutation, stamp the results panel "inputs changed — re-solve" (or clear the summary).*

**12. Number inputs accept out-of-range and cleared values silently.**
`src/ui/app.ts:113-118` (`numInput`) and :195-199 (resource `w`) commit `Number(input.value)` with no
clamping to the declared min/max: typing 9 into Interplanetary Consolidation stores `icLevel: 9`
(summary happily shows "10 planets"; the error only surfaces later as a caught solve failure), and clearing
any field commits `Number('') === 0` — e.g. a resource `w` of 0, silently dropped from the world by
`toWorld`'s `r.w > 0` filter (:70). Nothing throws (solve errors are caught and shown), but state accepts
values the UI's own `min`/`max` promise to prevent. (The `change`-vs-`input` choice itself is fine —
blur/Enter commits before a Solve click lands.)
*Fix: clamp in `numInput` (`Number.isFinite` + min/max) before writing state.*

### COSMETIC — dead weight, presentation, latent

**13. Autosave-restore banner is dead markup: restore is silent, "Discard" unreachable.**
`static/index.html:143-147` (`#autosaveRestore`, `#autosaveRestoreBtn`, `#autosaveDiscardBtn`) — zero
references in `src/` or `static/legacy/`; `loadState()` (src/ui/state.ts:70-85) restores unconditionally.
The banner ships `hidden` forever, so nothing visibly breaks, but the promised decline path doesn't exist
(only "Reset Everything" approximates it).
*Fix: remove the markup, or gate loadState behind the banner.*

**14. `#calcAnnounce` live region is never written — solves are not announced to screen readers.**
`static/index.html:227`; zero writers anywhere (v8's calc announced into it). `aria-live` on
`#resultsPanel` (:328) partially compensates.
*Fix: set its text in `runSolve()`.*

**15. Sticky solve bar is forced always-visible but the body reserves the wrong padding.**
`static/css/03-v9.css:42` (`#stickyCalc{display:flex}`) overrides 02-app.css:481's `display:none`, but the
matching `body.has-sticky{padding-bottom:96px}` (02-app.css:487) is class-gated and nothing ever adds
`has-sticky`; the body's default 80px (02-app.css:3) is what keeps the bar from covering the footer — a
~16px shortfall by the skin's own numbers.
*Fix: add `body{padding-bottom:96px}` to 03-v9.css (or add the class in wireShell).*

**16. `#tooltip` is a dead element.**
`static/index.html:62`, styled at 02-app.css:267 — no code in `static/legacy/` or `src/` references it
(v8's tooltip machinery wasn't carried; 19 uses `#selectorPopup` instead). Harmless (hidden by default).
*Fix: delete it, or delete this line of the report when the tooltip returns.*

**17. `#heroCommodityCount` is hardcoded.**
`static/index.html:160` — static "101"; nothing updates it. Currently *correct* (83 PI + 7 composites +
11 bought inputs = `priceableNames().length`), but it will silently rot if the sets change.
*Fix: set it from `priceableNames().length` at load.*

**18. The Rajdhani font `@import` points at a cdnjs path that almost certainly 404s.**
`static/css/01-tokens.css:1` — `https://cdnjs.cloudflare.com/ajax/libs/rajdhani/1.0.0/rajdhani.min.css`:
cdnjs hosts no "rajdhani" library (it is a Google Font); could not be network-verified from this sandbox.
If dead, `--font-display` silently falls back to Arial Narrow — the h1/brand never render in the intended
face. The second import (Google Fonts Inter/JetBrains Mono) is a real URL.
*Fix: move Rajdhani into the Google Fonts css2 import.*

**19. Duplicate skip links.**
`static/index.html:28-29` — "Skip to the planner" (`#main`) and "Skip to planner" (`#sec1`) back to back;
both targets exist and work, but two near-identical links is one too many for keyboard users.
*Fix: keep one.*

**20. `baseCostOf` is latently broken twice over.**
`static/legacy/01-data.js:1026-1028` guards on `typeof tierOf === 'function'` — no legacy file defines a
global `tierOf` (v9's is module-scoped in app.js; 00-shims deliberately named its version `v9TierKey`), so
it would return null for every PI commodity even before considering that `TIER_BASE_COSTS` (:1010) is in
TDZ after defect #2. No current caller, so cosmetic — until something calls it.
*Fix: point it at `v9TierKey` (and resolve #2).*
